# 04 — Canais e apps

Como as lógicas de negócio chegam ao usuário final.

## Visão dos canais

| Canal | Entrada | Domínios principais |
|-------|---------|---------------------|
| Telegram Bot | Webhook `POST /api/telegram/webhook` | Quase todo o campo + admin |
| UI Externa | Browser mobile-first → REST `/api/v1` | Agenda OS, CTO, cliente, estoque, ONU, suporte |
| UI Interna | Browser desktop → REST `/api/v1` | Financeiro, assuntos, rastreador |
| MCP Admin | Streamable HTTP `/api/mcp` | Consultas admin / AI |
| Services | `/api/services/*` | Health, utilitários, finalização OS (legado/CRM) |

---

## 1. API REST (`/api/v1`)

Auth: **JWT Bearer** (`POST /api/v1/auth/login` com email/senha do funcionário). Também: `check-token`, `regenerate-token`. Token ~1h com payload do funcionário.

### Mapa de controllers (agrupado)

| Prefixo | Responsabilidade |
|---------|------------------|
| `auth` | Login e tokens |
| `os` | Agenda, detalhes, deslocamento, execução, reagendar, finalizar, arquivos, perguntas, produtos |
| `os/assuntos` | CRUD de configuração de assuntos |
| `cto` | Próxima, sinais, arquivos, relatório PDF |
| `clientes` | Detalhes, histórico sinal, Wi-Fi, acesso remoto, CTOs próximas |
| `estoque` | PDF, requisição, transferência |
| `onu` | Autorizar |
| `despesas` | Lançar |
| `suporte` | Auxílio |
| `funcionarios` | Listagem/detalhe |
| `localizacoes/funcionarios` | Posição atual / listagens |
| `financeiro/*` | Fechamento, transferência, recebimento, vistoria, movimentação, depreciação |
| `elementos` | Elementos de rede |
| `metricas` | Telemetria de produto |
| `monitoramento/ao-vivo` | Feed para rastreador |

Swagger descreve os endpoints como alinhados aos fluxos do Telegram.

### Outros endpoints HTTP

| Path | Função |
|------|--------|
| `/api/services/*` | Health, mudar/desmudar IDs IXC, movimento produtos, baixar faturas, login aplicativo, finalizar OS |
| `/api/pdf/:filename` | Servir PDFs gerados |
| `/api/telegram/webhook` | Updates do Bot API |
| `/api/mcp` | MCP Streamable HTTP |
| `/api/auth/*` | Login OAuth MCP |
| `/.well-known/...` | Discovery OAuth (fora do prefixo `/api`) |

## 2. Telegram Bot (in-process)

Mapa de features: `apps/api/src/application/features/telegram/telegram.feature.map.ts`.

### Grupos funcionais

## 7. Como o app “funciona” no dia a dia (narrativa)

### Técnico de campo

1. Faz login (Telegram ou UI externa)
2. Ativa/compartilha localização
3. Abre a agenda → inicia deslocamento → chega no cliente → inicia execução (motivo, tempo, fotos)
4. Durante o atendimento: mensagens, produtos, CTO/sinal, ONU se necessário
5. Solicita finalização → CRM/apoio revisa → OS fecha no IXC
6. Pode requisitar material, lançar despesa, pedir suporte

### Supervisão / financeiro

1. Acompanha técnicos no rastreador (status DS/EX, alertas)
2. Configura assuntos (compliance da OS)
3. Opera fluxo de caixas: fechar → transferir → receber → vistoriar

### Automação (sem usuário)

- Provisiona ONUs, envia WhatsApps, valida PIX, sincroniza usuários/fibra/almoxarifado, notifica financeiro
