# 02 — Arquitetura atual

## Monorepo

| Item | Detalhe |
|------|---------|
| Orquestração | **Nx** 22 + **pnpm** workspaces |
| Apps | `apps/api`, `apps/ui-external`, `apps/ui-internal` |
| Libs compartilhadas | Pasta `libs/` não populada no momento |
| Linguagem | TypeScript em todos os apps |
| Dev local | `pnpm dev` — API + duas UIs via `concurrently` |

```
gigacenter/
├── apps/
│   ├── api/                 # NestJS — núcleo
│   ├── ui-external/         # React/Vite — campo
│   └── ui-internal/         # React/Vite — interno
├── storage/pdfs/            # PDFs gerados

├── nest-cli.json
├── nx.json

```

## Stack por camada

| Camada | Tecnologia |
|--------|------------|
| API | NestJS 11 (Express), Swagger, Socket.IO, `@nestjs/schedule` |
| App DB | MongoDB + Mongoose (`APP_DB_URL`) |
| ERP DB | MySQL + TypeORM (schema `ixcprovedor`) |
| OPA | MongoDB (OPA Suite) + API HTTP |
| Frontends | React 19, Vite 8, Tailwind 4, Radix, TanStack Query, Zustand, React Router, Framer Motion |
| Mapas | Leaflet / Mapbox (`VITE_MAPBOX_TOKEN`) |
| PDF | Puppeteer + Chromium (imagem Docker da API) |
| Auth | JWT Bearer; OAuth próprio para MCP |
| AI | OpenAI SDK; MCP via `@modelcontextprotocol/sdk` + `@rekog/mcp-nest` |

## Apps e portas

| App | Dev | Deploy | Papel |
|-----|-----|--------|-------|
| `api` | `PORT` (ex.: 17500) | Docker `ghcr.io/typedbywill/gigacenter` | REST, Telegram webhook, cron, MCP, Socket.IO |
| `ui-external` | 4200 | Nginx Alpine | Agenda OS, CTO, cliente, estoque, ONU, suporte |
| `ui-internal` | 4300 | Nginx Alpine | Financeiro, assuntos OS, rastreador |

Prefixo HTTP global da API: **`/api`**. Swagger em `/api/docs` (quando habilitado).

## Camadas da API (`apps/api/src`)

```
application/          # Casos de uso + features de entrada
  api/v1/             # Controllers REST versionados
  api/services/       # Endpoints utilitários / legado / health
  features/telegram/  # Handlers do bot
  use-cases/          # Lógica compartilhada (HTTP + Telegram)
  routines/           # Jobs agendados
  mcp/                # Servidor MCP admin
  field-policies/     # Políticas de execução em campo (GPS, bloqueios)
infrastructure/       # Adapters: IXC, OPA, Telegram, WAHA, CRM, PDF, ONU…
shared/               # Middleware e helpers transversais
constants.ts          # Limiares de sinal, cidades, tracking, admin chats
```

### Padrão de fluxo

1. **Entrada** — controller Nest, feature Telegram ou tool MCP  
2. **Política** — JWT, localização fresca (≤ ~10 min), bloqueios Telegram  
3. **Use-case** — orquestra regras e chama adapters  
4. **Infrastructure** — IXC DB/API, Mongo app, CRM, NOC, etc.

## Deploy atual

- Build/push Docker via scripts npm (`api:docker:deploy`, `ui-*:docker:deploy`, `docker:deploy`)
- Registry: **GHCR**
- **Sem** manifests Kubernetes, docker-compose ou workflows `.github` no repo
- Timezone da imagem API: `America/Sao_Paulo`, locale `pt_BR`

## Decisões relevantes (e dívida técnica)

| Decisão | Efeito |
|---------|--------|
| Use-cases compartilhados | Evita divergência Telegram vs HTTP |
| Processo monolítico | Bot + cron + MCP + REST no mesmo processo Nest |
| Cache em Mongo | Sem Redis; simples, mas acoplado ao DB app |
| Sem message broker | Rotinas e WAHA em cron in-process (ex.: WhatsApp a cada 5s) |
| Senha de login | Comparação direta no path atual (helper de hash existe, mas não é o fluxo principal) |
| Config geográfica hardcoded | `CIDADES`, `ADMIN_CHAT_IDS` em código |
